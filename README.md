# sql.fm-mcp

A proposed read-only [Model Context Protocol](https://modelcontextprotocol.io) server for the
[SQL.FM](https://sql.fm/) SQL Server feature matrix — so ChatGPT, Claude, Codex, and other MCP
clients can answer SQL Server version, edition, and Azure SQL support questions from a cited
reference instead of from memory.

## Summary of the recommendation

A stateless TypeScript **Cloudflare Worker** at `https://sql.fm/mcp`, built on **MCP SDK v2**
(spec `2026-07-28`) and Cloudflare's `createMcpHandler`, serving a versioned `dataset.v1.json`
generated by the *existing SQL.FM build* and bundled at deploy time.

Three read-only tools:

| Tool | Purpose |
|---|---|
| `search` | Find features by name, keyword, or natural language. Returns canonical sql.fm URLs for citation |
| `fetch` | Full record for one feature: support across all releases and editions, Azure status, history, conditions, Microsoft docs |
| `compare_feature_support` | Compare one feature across chosen SQL Server versions, editions, and Azure environments |

Plus three MCP resources (`sqlfm://environments`, `sqlfm://categories`, `sqlfm://dataset/meta`).

The server **never** executes SQL, connects to a database, fetches a user-supplied URL, or
writes anything. It reports the dataset's recorded status and qualifications — it does not infer
them, and it never converts unknown or not-applicable data into "unsupported".

## Data use and permission

SQL.FM's data belongs to Mike Scalise. Until permission is explicitly confirmed:

- **No SQL.FM data is committed to this repository.** `data/dataset.v1.json` is gitignored.
- Development and tests run entirely against **small synthetic fixtures** with invented feature
  names — no SQL.FM content.
- No provider that reads sql.fm at runtime is enabled by default, and no scraping provider is
  designed or built.

See [§4 of the design](docs/architecture.md#4-permission-ownership-and-what-this-design-refuses-to-do)
for the full permission boundary, including what `sql.fm/robots.txt` currently signals.
